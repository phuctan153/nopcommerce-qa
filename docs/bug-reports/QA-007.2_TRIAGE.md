### TRIAGE-001: filter availability

The case requires an enabled filter with known matching and nonmatching products on the same listing. Its expected result concerns applying and clearing that filter. The historical observation describes absence of a control, not a filter producing incorrect results. No listing URL, chosen filter, or representative products were recorded.

Filtering availability is configurable. The official [category settings](https://docs.nopcommerce.com/en/running-your-store/catalog/categories.html) describe enabling price-range filtering per category. [Catalog settings](https://docs.nopcommerce.com/en/running-your-store/catalog/catalog-settings.html) separately describe price filtering on search and tag pages. These sources explain why the precondition matters; they do not establish the setting on the original public listing.

Next verification: select a listing with a visibly enabled filter and two suitable products, then compare the unfiltered, filtered, and cleared states. If no suitable control can be found, record a fixture/configuration blocker instead of a new Fail.

### TRIAGE-002: required option fixture

The case requires a purchasable product with an independently established required option that can be left unset. The data record explicitly says to choose another fixture or record Blocked when every option is defaulted. A product with no option fields does not exercise missing-option validation.

The official [product setup guide](https://docs.nopcommerce.com/en/running-your-store/catalog/products/add-products.html) documents product-specific attributes and preselected values. The [attribute guide](https://docs.nopcommerce.com/en/running-your-store/catalog/products/product-attributes.html) also describes predefined selections. This does not prove that the unknown historical product had a required option.

Next verification: select another configurable product, establish one required but omittable option, leave only that option unset, and attempt Add to cart. Confirm both the validation message and empty cart. Do not force an invalid state through developer tools or alter public catalog configuration to manufacture the precondition.

### TRIAGE-003: guest checkout route

The case requires an eligible signed-out cart and an explicit guest option. The historical execution note already says that the guest option's availability was not established. The record does not show that an offered guest option was selected and then incorrectly required authentication.

The official [order settings](https://docs.nopcommerce.com/en/running-your-store/order-management/order-settings.html) describe the setting that allows anonymous checkout. Next verification: prepare a fresh eligible guest cart, start checkout, inspect the entire sign-in/checkout-choice page, and select the guest option only if offered.
